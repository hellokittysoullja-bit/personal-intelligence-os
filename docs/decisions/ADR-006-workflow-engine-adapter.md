# ADR-006: WorkflowEngine как адаптер (LangGraph.js первым)

- Статус: Принято
- Дата: 2026-08-05

## Контекст

Оркестратору нужен механизм выполнения многофазных, приостанавливаемых,
возобновляемых процессов (миссий). ТЗ прямо разрешает использовать
LangGraph.js как первую реализацию, но запрещает превращать его в
доменную модель проекта (принцип 1.2, раздел 9 ТЗ) и явно запрещает
использовать несколько workflow-фреймворков одновременно (раздел 2).

## Решение

Домен определяет интерфейс `WorkflowEngine` (`start, pause, resume,
cancel, signal, getState, checkpoint`, эмиссия событий, история переходов
— см. `ARCHITECTURE.md` §5, §7). Первая реализация — `LangGraphWorkflowEngine`
в `packages/workflow-engine`. LangGraph-специфичные типы не пересекают
границу этого пакета — наружу торчит только доменный интерфейс. Главный
граф LangGraph состоит из небольшого числа фаз высокого уровня (раздел 4
ARCHITECTURE.md: UNDERSTAND→CONTRACT→PLAN→EXECUTE→VERIFY→CORRECT|COMPLETE→
LEARN→FINISH на старте, расширяется до полного цикла из раздела 7 ТЗ по
мере milestone). Динамика внутри EXECUTE (граф задач, параллелизм,
субагенты) моделируется доменными сущностями `TaskGraph`/`Task`/`AgentJob`,
а не отдельным статическим узлом LangGraph на каждую возможную роль —
иначе граф начинает дублировать доменную модель и разрастается
неограниченно.

## Обоснование

- Прямое требование ТЗ (разделы 1.2, 9, 22 п.5, 24).
- Позволяет заменить LangGraph на `LocalWorkflowEngine` (для тестов без
  внешней зависимости) или `TemporalWorkflowEngine` (для долгоживущих
  процессов, Milestone 10) без изменения `orchestrator-core` — прямой
  критерий качества фундамента.
- Ограничение «граф — это фазы, не роли» защищает от анти-паттерна, при
  котором workflow-граф превращается в теневую копию доменной модели.

## Альтернативы

- **CrewAI как основной механизм выполнения команд** — отклонено на
  первом этапе явным требованием ТЗ (раздел 1.2, раздел 2); может быть
  подключён позже как отдельный `TeamExecutionEngine` за тем же типом
  порта, если появится конкретная потребность.
- **Temporal с первого дня** — отклонено: операционная сложность
  (отдельный сервер, воркеры) не оправдана на этапе, когда даже базовый
  цикл миссии не реализован; явно запланировано на Milestone 10.
- **Полностью самописный workflow-движок без LangGraph** — рассмотрено,
  но отклонено для первой итерации: LangGraph.js закрывает потребность в
  checkpoint/resume/graph execution «из коробки», а адаптерный слой уже
  устраняет риск vendor lock, ради которого стоило бы писать своё с нуля.

## Последствия

- Любой код, использующий `StateGraph`, `Annotation` и другие типы
  LangGraph, живёт исключительно в `packages/workflow-engine/src/langgraph/`
  (точное имя папки фиксируется при реализации).
- Checkpoint/resume миссии реализуется через доменный `checkpoint()`/
  `getState()`, что делает возможным написать `LocalWorkflowEngine` без
  LangGraph для быстрых unit-тестов домена, если это понадобится раньше
  Milestone 10.
