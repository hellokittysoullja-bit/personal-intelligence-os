# ADR-002: TypeScript (strict) как основной язык

- Статус: Принято
- Дата: 2026-08-05

## Контекст

Проекту нужен единый язык для домена, API, worker'а, web-интерфейса и
скриптов автоматизации, с сильной типизацией (доменная модель PIOS
включает десятки связанных сущностей и статусов — раздел 5–6 ТЗ), хорошей
экосистемой для Fastify/Next.js/Playwright/LangGraph.js и возможностью
делить типы между backend и frontend без дублирования.

## Решение

TypeScript в строгом режиме (`strict: true`) — основной язык всего
репозитория: domain, application, infrastructure-адаптеры, API, worker,
web. Общие типы и Zod-схемы переиспользуются между `apps/api`, `apps/worker`
и `apps/web` через `packages/domain` и `packages/contracts`.

## Обоснование

- Явное требование ТЗ (раздел 3).
- Один язык для всего стека (включая Next.js/React) уменьшает когнитивную
  нагрузку и дублирование типов между frontend/backend.
- Zod поверх TypeScript даёт одновременно compile-time и runtime
  валидацию — критично, поскольку любое состояние от LLM обязано
  проходить schema-валидацию (раздел 23.13 ТЗ).
- Строгий режим (`strict`, без `any` без крайней необходимости) снижает
  вероятность классов ошибок, недопустимых для системы, управляющей
  реальными инструментами и деньгами/данными владельца.

## Альтернативы

- **Python** — отклонено: несмотря на богатую AI-экосистему, слабее для
  единого full-stack (web+api) решения на Next.js; смешение Python+TS
  добавило бы границу сериализации без явной выгоды на этом этапе.
- **Go** — отклонено: не подходит для Next.js frontend, менее удобен для
  быстрой итерации над доменной моделью с частыми изменениями схем.

## Последствия

- Любой `any` требует явного обоснования (комментарий) и по возможности
  замены на `unknown` + сужение типа.
- Ошибки TypeScript не подавляются (`@ts-ignore` и подобное — запрещены
  без явного обоснования, см. `DEVELOPMENT.md`).
- Отдельные будущие компоненты (например, потенциальный ML-препроцессинг)
  могут потребовать пересмотра — решается отдельным ADR в момент
  необходимости, не предвосхищается сейчас.
